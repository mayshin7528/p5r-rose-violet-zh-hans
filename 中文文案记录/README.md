# 中文文案记录说明

这个目录只管“给人看的中文文案”。它不是编译源文件，也不替代 `.msg / .BMD / .BF`，作用是方便审稿、改称呼、查语气和回看某批翻译到底写成了什么。

## 先看索引

当前记录入口：

- [索引.md](./索引.md)

索引按“主线剧情对话”和“开场赌场补漏”整理了当前所有记录、状态和下一批入口。旧记录暂不移动、不改名，避免破坏交接文档里的引用。

后续新增记录时，先按本 README 的格式写正文，再把新记录补进索引。

## 记录规则

每完成一批翻译，就新增一份记录：

```text
YYYY-MM-DD_范围说明.md
```

推荐范围：

- 一个 `.BMD.msg`
- 一个 `.BF` 反编译出来的 `.msg`
- 几个连续小文件
- 一组同模块文本，例如右上角气泡、地图内对话框、CG 字幕、目标指引

不推荐把同一个场景里的所有来源混成一份记录。比如“开场赌场”可能同时包含剧情 `BMD`、地图 `FSCR / FHIT`、右上角气泡 `SUPPORT`、目标指引 `MISSION_LIST.TBL`、CG 字幕等多条链路，应按模块拆开记录。

推荐命名示例：

- `YYYY-MM-DD_E106_001_剧情对话与选项.md`
- `YYYY-MM-DD_开场赌场右上气泡补修.md`
- `YYYY-MM-DD_开场赌场CG字幕补修.md`
- `YYYY-MM-DD_四轩茶屋FHIT路人对话补修.md`

## 每份记录至少包含

- 翻译范围
- 实际生效文件
- 编译 / 部署 / 日志 / 游戏实测状态
- 中文文案清单
- 待确认名称或称呼
- 修改备注

## 状态写法

建议统一用这几种：

- `已实测通过`：游戏里看到了中文，且无闪退
- `已部署待实测`：已同步到已安装模组，但当前没有对应存档确认
- `已部署待复测`：用户曾经在相关场景发现英文，补丁已部署，等待再次进同场景确认
- `已编译待部署`：编译通过，但还没放进已安装模组
- `草稿`：只完成文案，还没进入编译链

当前用户没有任何旧存档。后续很多文本会长期停留在 `已部署待实测`，这是正常状态，不代表该批没有完成编译或部署。

如果只能从新游戏开场赌场确认补丁可加载、缓存可重建、游戏不闪退，但看不到该批目标剧情文本，则仍记为 `已部署待实测`。


## 审稿方式

人工审稿时优先看“中文文案”列：

- 角色口气是否自然
- 人名、称呼、术语是否统一
- `Rose` 是否按当前规则保留英文
- 怪盗代号是否按当前规则保留英文
- `Inari` 是否按当前规则译为“小狐狸”
- 有没有过长、绕口、机翻感重的句子
- 整体用词、语气是否往原作官方中文靠拢
- 是否需要写入 `名字和称呼统一表.md`

审完如果要改，先改实际源文件，再同步更新这里，不要只改这份记录。
